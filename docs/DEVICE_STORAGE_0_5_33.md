# MPA 0.5.33 — device folders, explicit backup and safe offline cleanup

Delivered at tested application `7714d96b6f8b654c8f16e6358dd9d993356380fe`. [Validation and remaining acceptance](releases/v0.5.33.md). Return to the optional Processor discussion. Baseline is published 0.5.32; target is 0.5.33 / 44. No Processor or object-search rewrite is included.

1. Make Android device-photo access discoverable from Photos and Collections. Query the image/video collections in bounded batches, respecting full, partial and revoked access. Keep existing canonical device identities and camera files. Add coverage for media owned by a different Android application, rather than relying only on MPA-created fixtures.
2. Add Collections > On this device, with Camera and other directories, useful covers/counts, folder-specific paged galleries, viewer/selection and stable navigation/anchors. Retain volumes in folder identity. Persist only directory metadata, without duplicating media.
3. Show Back up for every readable local photo without a verified Drive copy. Explicit backup includes the readable original and available portable metadata (dates, location when Android permits it, labels, people, albums and edits). Keep face embeddings/crops private. Capture the destination, checkpoint original and metadata independently, verify both, preserve successful uploads on retry, and never enable automatic uploads implicitly. Explain optional Android location access and any unavailable metadata.
4. Provide Free up space with a count/size preview and confirmation. Clear only MPA-owned, freshly verified Drive downloads; retain thumbnails/indexes. Preserve camera files, local-only imports/edits, pins, drafts, active readers and pending jobs. Recheck protection at deletion time, continue after recoverable per-item errors, report actual reclaimed bytes and retained items, and propagate cancellation/unexpected invariant failures. Route budget enforcement through the same safe removal contract.
5. Add an additive Room 11-to-12 migration for directory and explicit metadata-backup checkpoints. Historical schemas remain unchanged; no destructive migration or original rewrite. Validate populated upgrades and existing checkpoints.
6. Run focused correctness tests plus full unit/lint/build and native API29/35/37 checks at one immutable application revision. Inspect captures, complete logs, warning provenance, schema changes and established upgrade signer. Preserve prior assertions. Publish the exact verified APK under the existing authorization; stop for a necessary decision or unresolved blocker. Existing diagnostic exceptions remain narrow.

Acceptance limits: physical S23 Ultra, live Drive/authentication and human TalkBack remain unverified unless actually exercised. A permission denial must remain an actionable access state, not an empty-library claim. A successful original upload with pending metadata must remain recoverable and must not be silently marked fully backed up.

Compatibility review: typed MediaStore views on Android 8 do not expose media_type, and the legacy video view omits orientation. Discovery and original verification share a version-aware projection; executable legacy-view queries cover API26–28 schemas. Cleanup confirmation supports scrolling at large font scale; native light/RTL action-target coverage is required. Directory paths/storage labels appear only where duplicate folder names need disambiguation.
