# MPA 0.5.22 — Drive access recovery

MPA previously captured one access token for a Drive gateway's whole lifetime. If Drive rejected it during a long transfer, work stopped and asked for reconnection; some entry points cleared the cache without obtaining a replacement and retrying. The owner reported repeated reconnect prompts. This fixes a demonstrated code path, while the precise frequency and all real-device causes remain unverified.

All production Drive gateway creation now supports exact-account/scope access renewal through Google AuthorizationClient. On an explicit HTTP 401, close the rejected response, clear the rejected cached token, obtain replacement access silently and retry the identical request **once**. Concurrent old-token rejections within a gateway share the replacement. Resumable uploads retain their session, byte range, body and persisted checkpoint. An HTTP 403, timeout, transport interruption or server failure does not trigger this authorization replay. A second 401 or an SDK consent requirement remains an actionable failure; no background consent screen is launched. Account/source guards remain, and tokens are never persisted or logged.

In-app import progress now says **Resume this import** or explains the actual failure. Historical Open MPA instructions are adapted only for display, including the secondary error text; saved failures, counts and checkpoints are unchanged. External notifications retain Open MPA guidance for stopped imports. Drive permission denials no longer automatically claim reconnecting is required, and a failed renewal does not assert that expiry is the proven cause.

For an import already stopped on an older version, open its details and choose **Import selected / Resume**. Automatic renewal handles a rejected access token during the retry. If Google actually requires consent, reconnect the affected account through Sources. This release does not restart intentionally paused/cancelled work or retarget a saved job.

Google Cloud OAuth configuration has not been inspected or changed. Google documents limited authorization lifetimes for apps in Testing; genuine recurring consent or revoked access still requires configuration/account evidence. [AuthorizationClient behavior](https://developers.google.com/android/reference/com/google/android/gms/auth/api/identity/AuthorizationClient) · [OAuth token expiration](https://developers.google.com/identity/protocols/oauth2/#expiration).
