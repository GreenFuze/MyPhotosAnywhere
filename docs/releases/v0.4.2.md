# MyPhotosAnywhere 0.4.2

MPA previously displayed “Google authorization canceled” for any consent activity result that was not OK, discarding result intents before Google’s SDK could report the actual error. This made setup failures difficult to diagnose after reinstalling or changing Drive access modes.

This update parses every returned Google authorization intent through the SDK and distinguishes consent cancellation, launch failure, missing result data, OAuth configuration error (code 10), network error (code 7), and other Google status codes. Successful authorization still requires the requested Drive scope and a verified matching account.

**Storage → Google setup details** displays and copies the actual installed version, package, signing SHA-1 and Drive scopes. The setup help is also available beside connection errors. These are public setup identifiers; no OAuth token, client secret or API key is displayed or copied.

Download **MPA-0.4.2-debug.apk** and install over 0.4.1. The established release signer and database schema are unchanged. Google Cloud configuration and live consent still require checking on your account; clearer diagnostics do not establish that Google has granted access. The 0.4.1 scanning/viewing/deletion fixes remain included.

Validated with **88 unit/integration tests, eight Android emulator tests and lint with zero errors**. The release signer and Room v5 schema match 0.4.1. Live Google authorization still needs a phone retry.

## Retry existing-folder authorization

1. Open Storage → Google setup details and confirm the installed version. Copy the setup details.
2. In the same Google Cloud project, confirm Drive API is enabled and an **Android** OAuth client has package `com.myphotosanywhere.mpa` with SHA-1 `A9:09:D0:BC:00:22:09:7F:9C:9F:B8:6F:E9:BC:E6:EF:60:44:C0:DD`.
3. In Audience, keep development in Testing and add the exact selected Google account as a test user. In Data Access, include `https://www.googleapis.com/auth/drive` for existing collections and `https://www.googleapis.com/auth/drive.file` for new MPA folders.
4. Choose Existing photo collection, then Choose Google account. Complete consent and select the photo folder. If authorization still fails, report the Google-screen error and MPA’s numeric code (or whether the screen closes without returning data).

The attached [Google setup guide](https://github.com/GreenFuze/MyPhotosAnywhere/blob/main/docs/GOOGLE_DRIVE_SETUP.md) includes a prompt for an agent running on your computer to inspect the existing Cloud project. Preserve older OAuth clients and signing keys; reinstalling again is not required for this update.
