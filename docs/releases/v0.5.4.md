# MyPhotosAnywhere 0.5.4 — Drive connection recovery

Version 0.5.4 / code 15 / Room v8. Update the existing installation; the established upgrade/OAuth signer and import checkpoints are preserved.

- Takeout ZIPs are read locally, then imported into the selected Google Drive destination. Drive destination checks and uploads require internet access to `www.googleapis.com`; Takeout import does not use the Photos Picker API. Storage now explains this requirement.
- Drive DNS failures, socket timeouts and interrupted connections show a clear connection message instead of leaving preparation as the only visible status. Up to three automatic retries use exponential WorkManager backoff starting at 30 seconds, respecting the destination's network settings. Waiting notifications remain visible between attempts.
- Retries retain staged files, reserved Drive IDs, upload sessions, acknowledged offsets and verified imports. A resumed upload probes the existing server session before continuing; a late network failure cannot resurrect a paused/cancelled job. Permission/authorization, invalid data and local storage errors remain fail-fast.
- Background foreground-service progress, the MPA status-bar icon and notification permission controls from 0.5.3 are included.

To test: pause the current import before updating, keep the original ZIP, then open **Storage**, allow notifications and choose **Import selected / Resume** on the same job. If DNS resolution still fails, restore a working Wi-Fi connection and inspect any VPN or Private DNS settings. Mobile data must also satisfy the destination's Wi-Fi-only preference. After automatic retries stop, resume manually once connectivity works. Do not create a replacement import merely to retry a connection failure.

Validated: 160 unit/integration tests, zero lint errors, CPU model checks, APK assembly and 21 native tests on each of Android 10/API 29 and Android 15/API 35 (42 total), with zero failures/errors/skips.
