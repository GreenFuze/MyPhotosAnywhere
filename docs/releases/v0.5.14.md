# MyPhotosAnywhere 0.5.14

[Download MPA-0.5.14-debug.apk](https://github.com/GreenFuze/MyPhotosAnywhere/releases/download/v0.5.14/MPA-0.5.14-debug.apk).

Install over the existing MPA app. Package `com.myphotosanywhere.mpa`, the established upgrade signer and Room schema 9 are preserved. No uninstall or app-data clearing is required.

## Changes

- The account button opens **Sources**. Activity, new imports and Settings have focused entry points. Selecting a source to manage it does not filter Photos. New imports show the default destination; saved jobs retain their captured destination. Source disconnection confirms the affected account/folder and preserved data.
- **Activity** separates Drive discovery/refresh, original downloads, on-device indexing and import progress. A compact gallery indicator opens it. Import details expand on demand; pause/resume/recovery controls and history dismissal/restoration reuse the existing durable job model. Import notifications open Activity.
- **Import photos** puts the destination and supported source choices first: Photos Picker, local Takeout ZIP parts, Drive ZIP and extracted folder. Detailed constraints remain available. No Takeout URL input was added.
- **Settings** separates Storage and cache, Recognition, Backup and metadata, Privacy and permissions, and About. Existing cache safety, recognition/map consent, XMP recovery/export and scheduling controls remain available. Workers, import checkpoints, captured destinations and original verification were retained.
- **People now shows imported Takeout labels** from `people[].name` values retained in photo metadata. Earlier imports need no reupload. Each label opens a chronological paged photo grid with the existing stable viewer/session/selection behavior. Details shows the exported names; the gesture remains **swipe up**.
- Imported names are **photo labels, not confirmed face assignments**. Equal names from different storage sources remain distinct, and imported labels are kept separate from reviewed MPA face identities. No faces/embeddings are fabricated, no identities are automatically merged, no recognition is silently enabled, and no originals or retained provider records are rewritten.

## Reconnect Google and resume an import

Open the top-right account icon > **Sources**, find the affected account/folder, tap **Manage source**, then **Reconnect** and approve Google's authorization prompt for that account. Return to **Activity**, expand the saved import with **View details**, and tap **Import selected / Resume**. Existing verified items and the job's captured destination remain; do not start a replacement import or remove the source to renew authorization.

## Limits and remaining acceptance

- **S23 Ultra acceptance and the previously reported JPEG crash remain unverified.** Real-account authorization, Samsung lifecycle behavior and the owner's particular Takeout ZIP have not been tested here.
- Only names actually present in matched, imported media sidecars can appear. This does not transfer Google's face models, face coordinates or unnamed groups. Imported labels are currently read-only and do not rename/merge reviewed people. Archived/excluded photos follow the normal query rules; use the appropriate Archive/Search context to browse them.
- At 100,000 indexed items, imported-label discovery measured 3.86–10.12s, a sparse first label page 0.49–1.28s, and its viewer snapshot 3.98–10.42s across CI emulators. These are fixture measurements, not phone guarantees. Discovery scans retained metadata on an IO dispatcher; media pages and cursor windows remain bounded. No new persistent full-text or people-membership table was added.
- Existing 100k Search no-match latency and selection/manual external-AI limitations remain. No mandatory server, paid AI or Google Photos backend dependency was introduced.
- One main UX batch remains: optional density/date-navigation gestures, motion and visual polish, followed by final device acceptance. Speculative Google feature parity remains separate work.
