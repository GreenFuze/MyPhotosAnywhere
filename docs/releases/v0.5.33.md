# MPA 0.5.33 — device folders and space cleanup

- Photos offers Android photo access directly. With permission, Camera and other device images/videos join the gallery automatically; unbacked device photos have no Drive badge.
- Collections > On this device groups readable photos by their actual directory and storage volume. Folder galleries use the existing paging, viewer and selection behavior.
- Back up is available for readable local photos without a verified Drive copy. Explicit backup sends the original and a separate, verified portable XMP file containing available dates, location, labels, people, albums and edit information. It does not enable automatic camera uploads. Private embeddings and face crops remain on this device.
- Original and annotation checkpoints are separate: retrying annotations reuses the verified original and reserved sidecar identity. Existing jobs retain their captured destination. Android may require separate permission for original location; previously retained originals remain unchanged.
- Sources > Free up space and Settings > Storage and cache show a size/count estimate and confirmation. Cleanup rechecks each Drive download before removal and keeps thumbnails and metadata. Camera files, local-only originals, offline pins, drafts, active readers and pending work are protected. Recoverable failures retain that file and allow other downloads to be processed.

Room 11-to-12 is additive: directory references and explicit metadata receipts only. Historical schema files, photo identities, originals and existing import/transfer checkpoints are preserved.

Physical Samsung S23 Ultra acceptance, live Google authorization/Drive transfers and human TalkBack remain unverified until exercised. The earlier JPEG crash remains unreproduced. Processor architecture and object-search changes are deferred.

Recognition clients now have scoped ownership through partial setup, cleanup failures and cancellation. A cancelled scan retains its input until the native task finishes, then releases its bitmap and file lease without committing cancelled results. Invalid model contracts still fail fast. The place editor ends dialog-owned text input before closing a valid edit; invalid coordinates stay editable.

Per-photo portable XMP upload does not introduce an automatic per-photo-sidecar restore interface. Existing catalog backup/restore is unchanged. Recognition embeddings and face crops remain local.

Isolated real-face probes identify the accurate detector and successful detection. The current model binaries/options match those probes. No supported delegate switch was identified; detection quality and logging were not changed to hide the warning.

- The owner approved publication with one earlier, unidentified API 35 “A resource failed to call release” warning documented. Real MPA ownership defects were fixed; final logs contain no resource-release or caught keyboard exception. Absence does not prove the old warning's cause or that every possible leak/race is fixed. The full API 37 acquisition stack identifies an Android-owned InsetsController/SurfaceControl object; API 35 did not reproduce the ordinary warning. Diagnostic binaries are not shipped or substituted for final acceptance. An intrusive tracing attempt and a failed local focused replay remain rejected and retained.
- The final API 37 pre-test Google Play services persistent SIM_STATE_CHANGED ANR matches the separately accepted service/broadcast scope. It precedes the first MPA test; host workload is not established as its cause. No MPA crash or ANR is accepted.

These are performance observations, not physical-device acceptance. JUnit's timing attribution makes no byte-identical CI test-APK claim because that APK was not archived.
