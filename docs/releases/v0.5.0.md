# MyPhotosAnywhere 0.5.0

MPA can now import selected Google Photos through the official Picker, read Google Photos Takeout ZIP parts or extracted folders, and convert Google media JSON discovered in connected Drive folders into MPA's portable metadata.

- Storage includes **Choose from Google Photos**, **Import Takeout ZIP parts** and **Import extracted Takeout folder**, with selection previews, pause/resume and visible unsupported items.
- Each job keeps its original Drive destination, reserved file IDs and resumable upload checkpoints. Verified duplicates in that destination can be reused. Completed migration staging is released; media remains in Drive and downloads on demand.
- Descriptions, capture time/location, unconfirmed people hints and the complete bounded Google media record survive the MPA XMP round trip. Existing MPA annotations take precedence; original media bytes stay untouched.
- After **Refresh Drive**, enable XMP annotation backup and the per-source **Convert and clean up Google metadata** option. MPA verifies the full Google record in the correct source's XMP backup before conditionally moving its JSON into reversible Drive trash. Unmatched, conflicting, album-level and unsupported JSON stays in Drive.
- Room v7 preserves existing photos, reviewed faces, upload sessions, destination choices and Drive scan checkpoints. The established upgrade signer, icon, face model and similarity thresholds are preserved.

## Setup and phone retest

1. Install **MPA-0.5.0-debug.apk** over the existing release without uninstalling. Storage → Google setup details should show **MPA 0.5.0 (11)**. Confirm your library and reviewed names survived.
2. Google Photos Picker needs **Google Photos Picker API** enabled and `https://www.googleapis.com/auth/photospicker.mediaitems.readonly` added in the existing Google Cloud project's consent/data access setup. Keep the existing Android OAuth client and test users. Browser automation failed to initialize during development, so this configuration has not been confirmed or changed.
3. Choose a default writable Drive destination. Import a small Takeout album from local/USB ZIP files or an extracted folder. Review metadata, pause/resume, add later ZIP parts explicitly, then repeat the import and check for extra remote copies.
4. Choose Google Photos, complete consent and selection, return to MPA, check completed selection and import selected items. Try a photo and video. Photos and Drive accounts are chosen separately.
5. Put a small unpacked Takeout media/JSON pair in a connected test folder and refresh. Opt into XMP backup and conversion. Confirm metadata in MPA and XMP, the unchanged media bytes, and the JSON in Drive trash only after backup verification. Test mismatched/ambiguous JSON; it must remain untouched.
6. Interrupt a transfer, restart MPA, change the default destination, and revoke/reconnect authorization. Existing jobs must keep their original destination and prior verified media.

Limits: 250 MiB per media file, 10,000 manifest entries, 128 KiB per Google JSON record, 2 MiB / 10,000 assets per XMP catalogue and 2,000 Picker items per session. Album membership comes from Takeout folders; album-level JSON conversion is not supported. Picker images omit location metadata and videos may be transcoded. Cloud document providers may download an archive internally; local/USB archives avoid that uncertainty.

This is a development release for phone acceptance. Synthetic regressions and native emulator checks do not prove real-account consent, Google Cloud configuration, provider behavior or Samsung background scheduling. See [setup and the full checklist](https://github.com/GreenFuze/MyPhotosAnywhere/blob/v0.5.0/docs/GOOGLE_IMPORTS.md).

Publication requires **125 unit/integration tests, 12 Android emulator tests, zero lint errors, CPU model checks and APK assembly** for one immutable source. The publisher verifies the established certificate and reuses that exact CI APK, recording evidence and checksums. Live Google account checks remain for the owner.
