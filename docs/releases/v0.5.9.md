# MyPhotosAnywhere 0.5.9 — Finished imports and safer image viewing

Version 0.5.9 / code 20 / Room v9. Update over your current installation. The established upgrade/OAuth signer, connected sources and saved transfer checkpoints are preserved.

- **Dismiss import** hides completed, cancelled and failed tasks in Storage. It preserves imported media, source ZIPs, task rows, staging and upload checkpoints. **Show dismissed imports** and **Restore import** recover hidden history; **Show more imports** exposes older entries. Active and paused work stays visible. A resumed failed import clears its dismissal.
- Dismissal persists after recreation/restart and clears its summary notification. A late terminal notification cannot repost a dismissed task. **Dismiss errors** remains available separately for acknowledging messages without hiding unfinished work.
- Image decoding is serialized across viewer pages, previews and tiles have heap-aware pixel bounds, and inactive pages release their detailed tile references. Preview/tile allocation failures show a recovery message or retain a usable preview instead of escaping the decode worker.
- Displayed bitmaps are released through Android's drawing lifecycle, without recycling frames that drawing may still use. Viewer paging stays stable while imports insert newer photos. Original reads validate the current database path and obtain a cache lease under the eviction lock; an evicted/missing original shows download recovery advice.

To test dismissal: open **Storage**, dismiss a cancelled or completed import, close/reopen MPA and confirm it stays hidden. Use **Show dismissed imports** and **Restore import** if you want its history again. Dismissal does not delete media or source archives. Continue your existing import rather than making another job to upgrade.

To test viewing: resume the import, open the downloaded image that previously crashed, zoom/swipe, close and reopen it while progress continues. These fixes address identified rendering, memory and cache-read hazards; the owner reported an intermittently crashing 2.5 MB JPEG on 0.5.8, but no device trace is available, so its exact cause is not confirmed. Native regressions verify drawing after tile replacement/close, injected decoder allocation failures, and a cached image kept open during synthetic import insertions/cache trimming. They do not prove every Samsung image/codec or system low-memory behavior. Please report whether the same image still crashes; capture a device crash log if it recurs.
