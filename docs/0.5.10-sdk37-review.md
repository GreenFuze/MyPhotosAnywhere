# SDK 37 behavior review for MPA 0.5.10

Status: source review completed; final API 29/35/37.0 native validation pending. S23 Ultra acceptance and the previously reported JPEG crash remain unverified.

The build targets API 37, retains minimum API 26 and Java 17, and uses the stable `platforms;android-37.0` SDK package. The native test matrix includes API 29, 35 and 37.0; the API 37.0 emulator uses the available Google APIs image.

## Permissions and privacy

MPA uses the Android document/photo pickers and existing persisted URI grants. This change introduces no broad media, location, LAN, microphone or contacts permission. Drive and Photos requests use public HTTPS services; no local-network discovery feature is being added. Existing recognition and map consent remain unchanged.

Both `allowBackup` and pre-Android-12 `fullBackupContent` remain disabled explicitly. Android 12+ cloud-backup and device-transfer rules exclude all private-data domains. Do not treat source reconnection or authentication failure as deletion of indexed media.

## Background work and notifications

Existing WorkManager foreground data-sync and user-initiated transfer contracts remain intact. WorkManager configuration reserves IDs 1–999999; durable import transfer IDs start at 1000000 and retain their existing preferences and namespace. Default WorkManager Startup initialization is removed so the application-provided configuration is used.

Notification permission checks and permission-revocation recovery remain in place. Notifications use standard layouts and bundled small icons, rather than unbounded photo bitmaps in RemoteViews. Activity entry points remain user actions or explicit notification actions; this release adds no background activity launch.

## Navigation, playback and memory

Existing Compose insets, system Back and measured floating-navigation clearance require native regression testing under target 37. Layout does not request fixed orientation or non-resizable behavior. Large fonts, RTL and light/dark navigation checks remain required.

Video playback must retain its visible-page and lifecycle controls under Android 17 background-audio restrictions. Original-image preview and region-decode limits, cancellation, cache leases and serial decoding remain unchanged. Drawing objects are reused during `onDraw`; the warning fix does not replace decoding or resource ownership.

No application reflection on private MessageQueue fields or mutation of static-final fields was found. The face model remains the same checksum-verified asset; the stable LiteRT replacement retains the Interpreter API and supplies native libraries with 16 KB ELF segment alignment. Native inference, detector, allocation and lifecycle checks remain required before publication.

## Network and sharing

Target-37 TLS behavior is delegated to the supported HTTP library and platform. Existing public-service authorization, payload verification, cancellation and retry behavior remain required. Sharing uses existing content URIs and explicit grant flags. This release adds no dynamic native-code loading from writable app storage.

References: [Android 17 target-specific changes](https://developer.android.com/about/versions/17/behavior-changes-17), [changes affecting all apps](https://developer.android.com/about/versions/17/behavior-changes-all), [LiteRT migration guidance](https://developers.google.com/edge/litert/migration).

Native stripping uses exact stable NDK r30 (`30.0.16248370`), verified against Android Developers downloads and Google SDK metadata on October 12, 2026. No keep-debug-symbols bypass is used.
