# MPA 0.5.22 — Drive access renewal and recovery wording

A long-running Drive gateway previously captured one access token for its whole lifetime. An explicit HTTP 401 stopped transfers and prompted reconnection; some entry points cleared the stale cached token but did not obtain a replacement and retry. This can explain interruptions during long imports, but does not establish every cause of the owner’s real-device reports.

All production Drive gateways now renew through the same exact-account/scope Google AuthorizationClient flow. An explicit 401 closes its response, clears only the rejected cached access token and requests a replacement silently. The identical request is retried once, including the same resumable-upload session, bytes and range. Concurrent rejections within a gateway share one renewal; a late old rejection cannot invalidate its replacement. No access token is persisted or logged. A second 401 or an SDK consent requirement remains actionable; no background consent UI is launched. Account/source identity validation remains at every entry point. Permissions/403, throttling, transport errors and server failures do not trigger this replay. Cancellation propagates and durable checkpoints remain authoritative.

In-app import statuses now say Resume this import or explain the actual failure. Known historical Open MPA navigation phrases are adapted only for display; stored errors and checkpoints are unchanged. External notifications retain an Open MPA instruction for stopped imports. Unexpected failure text remains visible. Drive access errors no longer claim that every 401 proves expired authorization, and a folder permission denial does not automatically tell the user to reconnect.

Google Cloud OAuth consent configuration is outside this release. Google documents limited authorization lifetimes for apps in Testing; no project mode has been inspected or changed. An actual recurring consent requirement still needs account/configuration evidence. [Google AuthorizationClient](https://developers.google.com/android/reference/com/google/android/gms/auth/api/identity/AuthorizationClient) · [OAuth token expiration](https://developers.google.com/identity/protocols/oauth2/#expiration).

Version 0.5.22/code 33; Room schema 9 and dependency versions unchanged. Visual Collections follows this focused reliability release. Real Google authorization/expiry on the S23 Ultra remains owner acceptance, distinct from synthetic HTTP and native regression checks.

A full native check also exposed a gallery restoration race during repeated layout switches: waiting for a changed layout-info object after a deferred scroll could time out at an already-current position. Placement retains a Compose frame boundary so paging/query recomposition can install its current immutable item provider, then uses Compose scrollToItem, which awaits attachment and forces synchronous remeasurement. The bounded timeout, canonical-ID alignment, eight-attempt invariant and all existing pixel-anchor assertions remain. No SQL, paging or viewer-session behavior is replaced.

API37 logs also exposed Google Play services SIM-state broadcast ANR before the first MPA test, while CI compiled APKs concurrently with emulator startup. Native CI now builds both APKs under the existing strict diagnostic gate before booting the emulator, then still runs the complete connected test suite and collects full boot/runtime logs. No Google service, test, assertion or diagnostic is disabled. Application code remains identical to the previously tested revision; final source validation still includes the CI ordering change.
