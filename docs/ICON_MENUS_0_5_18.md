# MPA 0.5.18 — icons and organized Settings

Settings uses icon-led menu rows grouped into Library, Backup and privacy, and Application. The existing section destinations and Back/rotation history remain. Sources provides Activity, Import and Settings icon shortcuts; the Add menu has leading icons. Selection and viewer actions use bundled vector icons with short visible labels. Viewer previous/next controls are 48dp labeled arrow icons around the position indicator, retaining gesture alternatives. The viewer Info icon opens the same Details sheet, also available by swipe up.

Each action keeps one complete accessible name, disabled state and selected state where relevant. Labels wrap at enlarged font sizes; actions wrap into more rows rather than becoming gesture-only or clipped. Menu rows are at least 64dp tall, actions at least 64dp, and icon-only Info remains 48dp. Destructive source and file actions retain explicit text and existing confirmation contracts.

The regression matrix exposed an intermittent viewer-return timeout. Source inspection found an unsafe one-shot restoration path: paging can prepend rows while restoration waits for the old row index to place its photo. Restoration now observes canonical identity snapshots and cancels/retries obsolete placements, with focused cancellation/prepend/removal tests. The existing nearest-item fallback and pixel-offset assertions remain.

This is otherwise a presentation increment. No changes to Room schema 9, queries, imports, workers, originals, cache leases, metadata, sources, consents or viewer lifecycle/gesture handling. Version 0.5.18/code 29 retains the established upgrade signer. Publication requires strict host and API 29/35/37 checks and independent verification of the exact CI APK. S23 Ultra acceptance remains pending. The owner could not reproduce the JPEG crash again; its cause remains unconfirmed.

Square and Mosaic now have distinct grid-composition lifetimes when their physical slot count changes. Each slot structure also owns its own LazyGridState, including measured-placeable caches. Only the canonical media/pixel anchor survives the structure change through the ViewModel; a state object is never transferred between incompatible grid nodes. The native regression repeats layout switches and checks the same photo/pixel offset before rotation and viewer return. This follows Compose's explicit identity mechanism ([Android lifecycle guidance](https://developer.android.com/develop/ui/compose/lifecycle)).

Failure-state diagnostics showed a correct saved canonical anchor while completed grid placement was six photos away. Placement now verifies the actual photo and pixel offset after completed measurement, and retries missing/misplaced results even without a key-list change. An impossible stable placement fails its internal invariant after eight completed attempts, with cancellation/removal still explicit; it cannot wait indefinitely while displaying restoration progress. Deterministic tests cover unchanged-key retries and invariant failure.

Explicit scroll requests use `requestScrollToItem` to apply the requested index during the next remeasure together with the updated item provider, then verify measured identity and pixels. The API's dataset-change semantics are documented in [AndroidX source](https://raw.githubusercontent.com/androidx/androidx/androidx-main/compose/foundation/foundation/src/commonMain/kotlin/androidx/compose/foundation/lazy/grid/LazyGridState.kt). This avoids forcing synchronous measurement against a preceding provider while new paging indices are arriving.

Grid geometry callbacks capture an immutable layout/density snapshot. They do not read a live delegated setting while a previous item provider is still being measured; spans, cell dimensions and physical slot count always describe the same layout. Focused native checks cover repeated switches, recreation, viewer return and import invalidation.

A real viewport boundary is recoverable: if the canonical photo is visible and scrolling in the required direction is exhausted, restoration accepts the nearest reachable pixel offset. It retains exact offsets whenever reachable. Three unit cases cover exact, clamped and still-reachable offsets. The import/viewer test now waits for a completed, visible gallery return before deleting its fixture.

Restoration waits for a changed measured LazyGridLayoutInfo after each deferred request; virtual Compose frame ticks alone do not count as completed placement. Measurement has a five-second wall-clock invariant guard, cancellation propagates, and exhausted placement diagnostics include the actual visible canonical keys/offsets. This matches Android's documented distinction between the [Compose test clock and Android measurement](https://developer.android.com/develop/ui/compose/testing/synchronization).

Restoration runs only while the screen lifecycle is STARTED. Backgrounding cancels pending measurement and its wall-clock guard; foregrounding restores the same canonical anchor. The existing continuity test includes a real background interval longer than the guard and verifies the returned photo/pixels. CI unlocks through WindowManager instead of sending MENU to a starting launcher, preventing the observed unrelated Pixel Launcher input ANR from covering native tests.
