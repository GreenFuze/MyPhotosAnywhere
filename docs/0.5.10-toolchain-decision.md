# MPA 0.5.10 toolchain warning decision

Status: owner approved this one upstream warning exception on October 12, 2026. All other warnings remain blocking. No suppression, severity reduction or baseline is applied.

The release plan requires stable toolchain versions, lint and Gradle warnings to fail the build, and an explicit decision for a warning that cannot be resolved safely.

The latest stable versions verified from official Maven metadata are Android Gradle Plugin 9.4.1, Kotlin 2.4.21 and KSP 2.3.12. Gradle 9.8.1 is the latest stable Gradle release. Lint reports `AndroidGradlePluginVersion` when the wrapper remains at 9.6.0.

With Gradle 9.8.1, AGP 9.4.1 emits:

> The Configuration.setVisible(boolean) method has been deprecated. This is scheduled to be removed in Gradle 11.

An isolated configuration-only project reproduces the warning with the same stable plugin versions. A deprecation trace identifies:

```
org.gradle.api.internal.artifacts.configurations.DefaultConfiguration.setVisible
com.android.build.gradle.internal.plugins.BasePlugin$Companion$createAndroidJdkImageConfiguration$1.execute(BasePlugin.kt:362)
com.android.build.gradle.internal.plugins.BasePlugin$Companion.createAndroidJdkImageConfiguration(BasePlugin.kt:367)
```

Even `gradlew help` fails under `org.gradle.warning.mode=fail`. The warning originates in AGP's JDK-image configuration, not application code or the project's task declarations. Changing application code cannot correct that third-party call.

The proposed choices are to retain the strict gate and wait for a stable upstream fix, or explicitly accept this one documented third-party warning with all other warnings still blocking. An accepted exception must remain visible in logs and release evidence; it must not be described as a zero-warning build.

Sources: [Gradle 9.8.1 release notes](https://docs.gradle.org/9.8.1/release-notes.html), [Gradle visibility deprecation](https://docs.gradle.org/9.8.1/userguide/upgrading_version_9.html#deprecate-visible-property), [AGP Maven metadata](https://dl.google.com/dl/android/maven2/com/android/tools/build/gradle/maven-metadata.xml).

Local evidence: `toolchain-probe.log` contains the complete trace and failed configuration-only result. `warning-build-5.log` records the newer-Gradle lint finding. All source, tests and release validation remain subject to the approved gate.

## Approved enforcement

The owner explicitly accepted this one warning rather than waiting for the maintainers to publish a compatible stable release. `scripts/gradle_checks.py` retains Gradle warning-failure mode and accepts its nonzero exit only when the fresh structured problems report identifies exclusively the exact AGP visibility deprecation and the sole build failure is Gradle’s warning-policy failure. Task failures, other diagnostics, compiler warnings and missing evidence block the build. Logs and the gate JSON retain the warning and original exit code. This is an explicitly documented upstream exception, not a zero-warning claim. Remove it when the supported stable toolchain no longer emits the warning.
